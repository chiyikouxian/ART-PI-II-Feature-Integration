# 系统架构文稿：从双手采集端到ROCK边缘计算再到前端可视化

---

## 一、总体架构概览

本系统是一套"双向手语翻译系统"，由三个物理层级和一个逻辑中枢组成，数据流从四周向中心聚拢，再从中枢向外分发。系统的四个核心角色分别是：左手采集端，基于ART-Pi2开发板搭载STM32H7S7L8Hx微控制器，负责11路IMU数据采集、VTX316语音合成和WiFi数据上行；右手采集端，同样基于ART-Pi2，负责11路IMU采集、麦克风语音助手和WiFi上行；ROCK边缘计算中枢，基于RK3588芯片，承担IMU数据汇聚、手语识别推理、二阶特殊动作审核和下行命令分发的核心职责；PC Web前端，采用Flask加Three.js技术栈，提供3D骨骼模型实时可视化、设备数据监控和AI引擎管理功能。整个系统的数据流向可以概括为：左右手采集端通过WiFi TCP以CSV格式将原始IMU数据以90毫秒一帧的速率发送至ROCK边缘计算节点，同时以JSON格式将滤波后的传感器数据以10Hz频率发送至PC Web前端；ROCK完成识别推理后，通过TCP下行命令将翻译文本和状态控制指令回传至双手端和PC端，形成完整的闭环。

---

## 二、第一层：双手采集端（嵌入式硬件层）

系统的数据源头是佩戴在用户左右手上的两只ART-Pi2开发板。每块ART-Pi2搭载意法半导体STM32H7S7L8Hx微控制器，内核为ARM Cortex-M7，主频高达480MHz，配备456KB的AXI SRAM和131MB以上的外部XSPI2 Flash存储，运行RT-Thread v5.1.0实时操作系统，板载CYW43438 WiFi加BLE双模无线通信模块。每只手通过两颗TCA9548A I2C多路复用器级联接入11个惯性测量单元：第一路I2C总线通过PB8和PB9引脚连接第一颗TCA9548A，其通道0到7各挂载一个MPU6050六轴传感器，提供加速度计三轴和陀螺仪三轴数据；第二路I2C总线通过PE1和PE2引脚连接第二颗TCA9548A，其通道0和1各挂载一个MPU6050，通道2挂载一个ICM-20948九轴传感器（额外包含磁力计三轴），通道3则挂载一块128乘64像素的SH1106 OLED显示屏。双手合计共22路空间运动采集通道，其中通道0到9为十个六轴传感器，贡献60个数据维度的手指局部动作信息，通道10为一个九轴传感器，贡献9个维度的手背整体姿态与地磁方向信息。

固件层面，RT-Thread上运行六个并发执行单元。主线程在初始化完成后进入500毫秒周期的LED心跳闪烁。初始化阶段启动一个优先级为20、栈空间2KB的iic_drv线程，一次性完成I2C互斥锁创建、两颗TCA9548A探测和OLED初始化后自动退出。随后系统进入稳态运行：优先级18的uart_oled线程占用2KB栈空间，负责UART1串口接收外部文本并按行解析后在OLED上三行滚动显示，同时每3秒刷新一次电池状态栏；优先级16的mpu6050线程分配了最大的4KB栈空间，以10Hz频率周期轮询全部11路IMU传感器，通过TCA9548A通道切换、I2C寄存器读取、指数移动平均滤波和陀螺零偏校准的完整管线，将处理后的数据存入共享内存结构体供上层模块通过mpu_get_channel_data接口读取；优先级22的bat_adc线程仅需1KB栈空间，以1Hz频率通过ADC1的通道12采集PC2引脚上的锂电池分压电压，经8次滑动平均滤波后映射为0到100的百分比电量；优先级同为22的tcp_cli线程占用4KB栈空间，负责WiFi TCP JSON数据上传，可通过MSH命令行动态启停。

左右手两端在功能上存在明确分工。双手共同具备11路IMU数据采集、WiFi TCP JSON上传、OLED实时显示和锂电池监测能力。左手端的独特之处在于集成了VTX316语音合成模块，通过UART1驱动，支持非阻塞式vtx316_speak和阻塞式vtx316_speak_wait两种播报模式，负责将ROCK回传的翻译文本转换为语音输出。右手端的独特之处在于集成了INMP441数字麦克风和语音活动检测模块，用于采集用户语音并对接AI云服务，实现语音到手语辅助提示方向的双向翻译扩展。

在数据采集管线上，每次读取先通过TCA9548A切换到目标通道，然后通过I2C读取MPU6050的14个寄存器或ICM-20948的20个寄存器获取原始值。原始值随即进入指数移动平均滤波器——MPU6050通道的滤波系数alpha设为0.25，ICM-20948通道的alpha设为0.10，在平滑噪声的同时保持足够的响应速度。陀螺仪零偏校准在启动阶段自动采集200个样本求均值作为零偏基线，此后每次读数自动扣除该偏置量。

每只手同时维护两条独立的上行数据通道。第一条是面向ROCK的CSV链路，通过WiFi TCP连接至192.168.221.239的9101端口（左手）或9102端口（右手），以90毫秒约11.1Hz的帧率发送格式为"[DATA]时间戳,hand类型,帧序号,69个原始整数值加换行符"的CSV帧，数据为未经滤波的原始传感器读数，专用于高实时性手语识别。第二条是面向PC的JSON链路，通过WiFi TCP连接至192.168.6.92的8266端口，以10Hz频率发送包含传感器对象和电池数据的结构化JSON帧，数据已经过滤波和校准处理，用于可视化监控。两条链路同时运行互不干扰，且均支持自动重连——TCP断开后等待约3秒自动重试直至恢复。

手套端同时监听TCP下行文本命令流。系统支持六种控制字：CMD:START使设备进入运行状态并开始数据流传输；CMD:STOP停止数据流并返回待机状态；CMD:RESET_SEQ重置帧序号计数器；MODE:MANUAL切换至手动模式，由ROCK通过CMD命令直接控制数据采集的启停；MODE:AUTO切换至自动模式，由本地姿态检测算法自动触发数据采集；SAY加文本内容在左手端触发VTX316语音播报并同时将翻译文本加入JSON上行帧，在右手端则仅记录日志而不执行本地语音播放。

## 三、第二层：ROCK 边缘计算中枢

ROCK是整个系统的计算核心和通信中枢，基于Rockchip RK3588芯片构建。RK3588采用八核CPU架构，包含四个Cortex-A76高性能核心和四个Cortex-A55高能效核心，内置6 TOPS算力的NPU神经网络处理器，运行Linux操作系统。ROCK在系统中扮演三重角色：边缘AI推理节点负责执行手语识别模型将IMU动作序列映射为自然语言文字，数据汇聚中心负责同时接收双手22路IMU通道的实时数据并进行时间对齐和空间配准，控制中枢负责向双手分发运行状态指令和翻译结果。

ROCK通过两个独立的TCP Server端口实现数据汇聚——9101端口接收左手CSV帧，9102端口接收右手CSV帧，每帧约90毫秒到达，帧格式为"[DATA]时间戳,hand类型,帧序号,69个原始整数值加换行符"，其中通道0到9各占6个字段共60个整数值，通道10占9个字段，无效通道自动填零保持帧格式不变。双手数据到达后进行时间戳对齐，将22个通道的IMU数据拼合为统一的动作特征向量，送入预训练的手语识别模型进行推理。

在自动运行模式下，系统采用两级检测架构以防止误触发和循环触发。第一级为本地粗检测，每只手独立执行，以200毫秒为周期轮询手背姿态、手指姿态和局部静止度三项指标，需要连续5次命中才进入RUNNING状态并开始WiFi CSV数据上行。第二级为ROCK端集中执行的二阶审核，使用更严格的阈值参数在多帧滑动窗口上进行波动检查和姿态复核。若审核通过则继续手语识别流程，若审核不通过则ROCK立即通过TCP下行命令将手套端强制退回自动待机状态，同时清除手套端的本地命中计数器和WiFi CSV帧序号，双重重置确保不会因残留状态而立即重新触发。

自动采集的完整扩展流程如下：本地姿态触发使手套进入RUNNING状态后开始CSV上行，ROCK审核通过后进入手语采集阶段；当检测到用户手势完成、手部回归自然下垂姿态时，手套自动进入WAITING_STOP状态暂停姿态检测以防止同一手势被重复采集；ROCK随后下发SAY加翻译文本命令，左手端通过VTX316语音播报；经过一段冷却期后，手套重新进入自动待机状态等待下一次手势触发。

## 四、第三层：PC Web 前端可视化

PC Web前端是整个系统的可视化呈现层和人机交互界面。后端采用Python 3加Flask框架，数据持久化使用轻量级SQLite数据库。前端界面基于Layui v2.13.3组件库构建，3D实时渲染引擎采用Three.js。实时通信方面，Flask内置TCP Socket Server监听8266端口，实现与双手套设备的双向JSON数据交互，同时暴露REST API供前端JavaScript以50毫秒周期轮询获取最新数据。系统围绕五个功能页面组织。

实时翻译页面是系统的核心可视化界面。Three.js加载GLB或GLTF格式的3D手部骨骼模型，前端通过Madgwick滤波器将加速度计和陀螺仪的原始六轴数据融合为姿态四元数，然后用四元数实时驱动骨骼模型中每个关节的旋转，实现左右手双设备同时渲染，帧率接近实时。用户还可以上传自定义骨骼模型以适配不同的手部结构，手势翻译的结果以文字形式实时叠加显示在3D视图旁。

设备数据监控页面以左右手双面板布局展示全部22个通道的传感器实时数据。每个通道的数据以表格形式列出6轴（通道0到9）或9轴（通道10）的原始数值，同时显示设备的TCP连接状态指示和电池电压电量信息，数据以50毫秒间隔刷新确保监控的实时性。

通道映射配置页面提供传感器物理通道到3D骨骼逻辑关节的映射管理。用户可以为左右手分别独立配置11个传感器通道对应的骨骼关节。系统内置了指尖关节联动逻辑——当第3节指骨发生旋转时，该旋转会自动传递并施加给第4节指尖指骨，模拟真实人手指弯曲时远端指节跟随近端指节联动的生物力学特性。

AI引擎管理页面允许用户通过标准OpenAI API范式接入第三方大语言模型服务。用户可配置多个模型方案，每个方案包含服务商名称、API端点地址、访问密钥和模型名称，支持随时切换和增删改查。页面内置聊天测试界面，可在不离开系统的情况下即时验证模型的效果和响应质量。

界面管理页面提供系统导航菜单的自定义配置能力，用户可以对菜单项进行重命名、拖拽排序和显隐控制，以适应不同使用场景下的界面布局需求。

前端与后端的数据衔接流程为：手套设备的JSON数据通过TCP到达Flask Server的8266端口后，服务器将数据缓存在内存中并同时维护设备连接状态。前端JavaScript以50毫秒为周期通过REST API的/api/device/latest端点拉取最新数据，然后依据用户配置的通道映射关系将各通道的传感器数值转换为对应骨骼关节的目标四元数，最终通过Three.js的动画循环驱动3D骨骼模型实时旋转。

## 五、端到端数据流全景

以下按一次完整的手语翻译流程，描述数据如何从指尖穿越整个系统。第一步，左右手共计22路IMU通过TCA9548A通道轮询和I2C寄存器读取完成原始数据采集，然后经过EMA指数移动平均滤波和陀螺零偏校准，存入共享内存结构体供上层模块读取。第二步，数据在采集端分叉为两条独立链路——面向ROCK的CSV链路发送未滤波的原始值，面向PC的JSON链路发送已滤波的结构化数据。第三步，CSV帧到达ROCK后进行时间戳对齐，将22通道IMU数据拼合为动作特征向量，送入预训练的手语识别模型推理出对应的文字结果。第四步，ROCK通过TCP下行发送SAY命令将识别出的翻译文本回传至左手端，左手端VTX316模块将文字合成语音播报，同时翻译文本也被附加到下一帧JSON上行数据中供PC端显示。第五步，JSON数据到达PC Flask服务器后，经通道映射和Madgwick融合生成四元数，驱动Three.js中的3D骨骼模型实时渲染当前手势姿态，同时AI引擎翻译结果叠加显示在界面上。

## 六、关键技术要点

I2C总线共享安全方面，I2C2总线被OLED显示屏和MPU6050传感器共享，系统采用互斥锁加上TCA9548A通道隔离加上GPIO重初始化的三重保护机制。每次操作前必须先获取互斥锁，通过TCA9548A禁用所有通道后再重新选择目标通道以确保通道缓存状态与实际硬件一致，OLED操作前还需调用OLED_I2C_Init重新配置PE1和PE2引脚状态。Madgwick传感器融合在前端侧将六轴IMU的加速度计和陀螺仪数据融合为姿态四元数，替代昂贵的九轴方案，计算量小且适合实时渲染场景。多设备TCP管理方面，Flask TCP Server采用线程安全设计，支持最多10个传感器设备并发连接，断线自动清理并支持设备重连。BLE和WiFi共存策略上，当前硬件阶段BLE与WiFi无法同时稳定运行，因此BLE相关代码保留在代码库中但运行时默认禁用初始化，优先保障WiFi TCP链路的稳定性，待后续硬件或驱动改进后再启用BLE链路。指尖联动映射中，通道映射将第3节指骨旋转自动传递至第4节指尖指骨，模拟真实手指弯曲时的骨骼联动关系。自动模式防循环方面，当ROCK二审拒绝本地触发后，同时清除手套端的本地命中累计计数器和WiFi CSV发送帧序号，双重重置确保不会因残留状态而立即重新触发进入循环。

## 七、物理部署拓扑

在物理部署层面，ROCK RK3588作为中心节点，IP地址为192.168.221.239，通过9101端口接收左手CSV数据和9102端口接收右手CSV数据。左手ART-Pi2和右手ART-Pi2分别通过WiFi连接至ROCK，左手端的MAC地址固定为C0:4E:51:05:34:33，集成11路IMU、VTX316语音合成模块和OLED显示屏；右手端集成11路IMU、INMP441数字麦克风、AI云服务接口和OLED显示屏。双手端同时通过WiFi JSON链路连接至PC Flask服务器（IP地址192.168.6.92）的8266端口。PC Flask服务器同时监听8266端口作为TCP Server接收设备数据，在5000端口提供Web界面服务，运行Three.js进行3D手部骨骼的实时渲染。
